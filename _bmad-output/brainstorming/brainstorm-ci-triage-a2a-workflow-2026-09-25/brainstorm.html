■ ROOT CAUSE · exit 1

Triage lacks evidence-backed confidence, so every wrong call costs trust and human coordination. The system must SHOW evidence and confidence, not only a verdict.

  • patchcoachEvidence-cited output schema: every claim must reference a log line / commit SHA / metric; a schema validator rejects uncited claims
  • patchcoachLow-confidence branch: confidence < threshold or conflicting signals → “needs human triage” punch-out with an evidence pack, no blame

can one cluster serve multiple repos?
  • answerlogYes, for all 3: one GitHub App on many repos; the payload carries repository + installation.id; mint a per-repo installation token per task; agents stateless, repo context in the task
  • ideacoachTenant isolation: history queries scoped by repo_id; LLM context never mixes repos; separate namespace only for different orgs / security boundaries
  • ideacoachRed-team cross-repo leakage with promptfoo bola/rbac plugins: an injected log tries to pull another repo’s history
many concurrent failures, or a queue?
  • answerlogNeed a queue: ack fast, bursts (broken main fails many PRs), Claude/GitHub rate limits, durability across restarts, retries, INPUT_REQUIRED tasks wait hours
  • ideacoachv1: Postgres jobs table with SELECT … FOR UPDATE SKIP LOCKED (also holds history + audit) or Redis Streams; N workers = concurrency cap
  • ideacoachDedupe/coalesce: same repo + fingerprint within a window → one triage, Triage Cards fanned out to all affected PRs
  • ideacoachPriority lanes: main/release failures ahead of feature-branch PRs
  • ideacoachPaused INPUT_REQUIRED tasks persisted in the DB, not held by a worker
